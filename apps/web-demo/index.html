Working with the map

				

					The map connects a desired result to the architecture and the route that will realise it.
					Each intention immediately begins a line; several intentions and alternative routes can be
					developed together.
				

				
    
					
  1. 
						Create an intention: describe the result and its observable criteria. It appears in the
						horizontal map immediately.
					
    2. 
					
  2. 
						Select its line and add a route. A route describes one way to realise that intention.
					
    3. 
					
  3. 
						Add architectural components and contracts or explanations. These are reusable records
						with stable identities.
					
    4. 
					
  4. 
						Add steps to the selected route. In each step, choose the existing components and
						explanations it uses. A step describes an action; a component describes part of the
						system.
					
    5. 
					
  5. 
						Select a step to reveal its linked records above. Use Edit to change it and Validate map
						to check the document.
					
    6. 
					
  6. 
						Apply a form, then save the map explicitly. File → Download JSON transfers the accepted
						map to another browser through Import.
					
    7. 
				

				
When actions become available

				
    
					
  • 
						Intention is always available. Other creation actions open after the first intention.
						Existing imported records remain available for editing.
					
    • 
					
  • 
						Route requires a selected intention. Route step requires a selected route; use its line
						to choose the destination.
					
    • 
					
  • 
						Intersection requires at least two existing intentions, steps, components or
						explanations. Its form stays inactive until two different sources are selected. Routes
						and estimates are excluded.
					
    • 
				

				
What an intersection means

				

					An intersection names a relationship worth explaining: for example, two steps depend on
					the same validation contract. Write the relationship in its note and choose its sources.
					Actual component reuse is expressed by both steps referencing the same component.
				

				

					Several intentions and shared architecture
				

				

					Add another intention to start another line. Add another route to explore an alternative
					for the same intention. Components and explanations can be shared across lines by
					identity; their names remain free to change. The arrows describe a route, while scheduling
					and time totals need a separate model.
				

				

					File format and storage
					

						Schema 2 is shared by CLI and WebAssembly. Language changes interface labels and help;
						authored text and machine IDs keep their original values. Maps are saved in this
						browser. JSON transfers the full map; Markdown provides a readable export.
