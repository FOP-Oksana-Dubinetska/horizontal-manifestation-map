# HMAP — авторская работа с картой, 2026-11-14

Статус: implementation candidate. Основание: прямое поручение владельца от 2026-11-14 завершить отложенный пользовательский сценарий и упростить интерфейс. Эта ограниченная программа уточняет roadmap-editor.plan.md §1.1, §14.3–14.5 и переносит формы из §22.6 в текущий выпуск. Исходная приёмка Stage 02.3a–14 сохраняет исторический объём.

## Chunk: `<<authoring-workspace>>`

Цель: пользователь создаёт карту, описывает намерения и архитектурные элементы, строит маршрут, связывает шаги с компонентами и контрактами, проверяет и сохраняет результат в браузере без внешнего редактирования JSON.

Вход: принятая карта schema 2, действия в формах, существующий C++/WASM engine и переданный storage. Выход: атомарно принятый RoadmapProject, отдельное состояние просмотра, одно уведомление onChange на принятое пользовательское изменение. Отмена и ошибка сохраняют последнюю принятую карту. Сохранение в storage остаётся явным действием host.

Границы: vanilla TypeScript, JSON schema 2, один видимый маршрут, текст сверху. Формы открываются в доступном модальном диалоге. Создание и изменение охватывают проект, намерения, маршруты, шаги, компоненты, фрагменты, пересечения и оценки. ID выдаются автоматически и сохраняются при изменении названия. Ссылки выбираются по именам существующих объектов. Порядок задаётся массивами. Перед удалением показан состав удаляемых объектов и снимаемых ссылок; изменения проверяются единым движком. Readonly запрещает пользовательскую запись. Feature flag editing выключает формы; импорт управляется отдельным флагом importButton. Programmatic setProject сохраняет прежний контракт.

Интерфейс: основной host использует русские инженерные подписи. Selector engineering/simple/product/literary выключен по умолчанию; совместимый opt-in API и формат файлов сохраняются. Удалены презентационная шапка, технический слоган и ссылка на пример встраивания из рабочего интерфейса. Служебный пример остаётся в документации интеграции. Стартовый пример показывает архитектурные компоненты и их повторное использование в нескольких маршрутах. Старые сохранённые карты сохраняются.

Вне объёма: schema 3 / WorkItem, TUI, cloud sync, авторизация, Canvas, произвольная обратная сборка Markdown, изменение политики CSP ради неизвестных content.js. Отчёт CSP из пользовательского браузера требует установления полного URL инициатора; приложение сохраняет внешние same-origin scripts и строгую CSP.

## Приёмка

1. Из пустой карты через UI создаются намерение, компонент, контракт, маршрут и шаг с двумя типами связей. После изменения текста, порядка и критериев JSON и Markdown содержат принятые значения.
2. Неверный кандидат (например цикл происхождения) сохраняет принятую карту и введённый текст формы, показывает диагностику C++.
3. Отмена формы, удаления или импорта сохраняет карту. Подтверждённое удаление снимает объявленные ссылки и сохраняет остальные сущности.
4. Два экземпляра независимы; readonly скрывает авторские действия; поздняя проверка/уничтожение не возвращают старую карту.
5. Основной интерфейс не показывает selector профиля, техническую шапку и слоган; маршрут остаётся одним горизонтальным рядом на 390 px. Диалог доступен клавиатурой.
6. Сохранение, повторное открытие нескольких карт, конфликт вкладок и ошибка квоты имеют наблюдаемый результат. Новый текст остаётся доступен для скачивания при отказе storage.
7. Проверки выполняются локально на исходной базе Stage 14. Неподтверждённые сообщения пользовательских расширений не объявляются исправленными.
