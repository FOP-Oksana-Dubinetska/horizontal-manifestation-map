# Stage 17 — рабочая страница автора

## 1. Что получаем

Компактную русскую страницу с созданием, изменением, проверкой, сохранением и открытием карт. Содержательный пример соединяет архитектуру с двумя маршрутами реализации через общие компоненты и контракты.

## 2. Файлы этого диффа

`apps/web-demo/index.html`, `main.ts`, `style.css`, `packages/roadmap-ui/src/index.ts`, `style.css`, `examples/architecture-workspace.roadmap.json`, `tools/build-web.mjs`, `tests/browser/editor.spec.ts`, `workspace.spec.ts`, `docs/authoring-guide.ru.md`, эта карточка и `TRACE.md`.

## 3. Контракт

Сохранение фиксирует принятую карту и текущий выбор маршрута; загрузка и форма сохраняют отдельные состояния. Старые карты открываются без переписывания, новый пример доступен через «Файл → Пример архитектуры». При ошибке storage текущий источник скачивается. Открытие другой карты требует решения о несохранённых данных. Metadata списка обновляются из собственного сохранения без повторного чтения и сброса конфликтов активного адаптера.

Верхняя презентационная шапка, технический слоган и ссылка на embedding fixture удалены. Selector терминологических профилей отсутствует на рабочей странице. Нажатие шага выделяет архитектуру и контракты; отдельная кнопка «Проверить карту» действительно вызывает validator.

## 4. Проверка

```powershell
npm run typecheck
npm run build
npm run test:web
```

Полный браузерный проход: 44/44 PASS (22 Chromium + 22 Firefox). Native validate нового примера: exit 0, Valid project. После визуального просмотра доработаны mobile-отступы; повторены затронутые layout и text/save/export сценарии: 4/4 PASS. Скриншоты проверены на desktop и 390px. Технические детали среды и ручные пункты остаются в TRACE.
