# Stage 16 — формы и атомарное принятие

## 1. Что получаем

Изменение текста и структуры карты через доступные формы. Шаг маршрута показывает связанные архитектурные компоненты и контракты. Формы сохраняют имена и ID раздельно и используют общий validator.

## 2. Файлы этого диффа

`packages/roadmap-ui/src/authoring-form.ts`, `index.ts`, `style.css`, `apps/web-demo/public/embedding-example.js`, `tests/browser/authoring.spec.ts`, уточнение `hmap-authoring.plan.md`, эта карточка и `TRACE.md`.

## 3. Контракт

Вход — копия последнего принятого проекта и действие автора. Форма собирает кандидат, C++/Wasm проверяет его целиком, затем UI заменяет состояние и вызывает onChange один раз. Ошибка сохраняет и карту, и введённый текст формы. Отмена, новый запрос и уничтожение блокируют поздний результат. Удаление показывает состав последствий до подтверждения. Сохранение в storage выполняет host отдельно.

`newProject()` открывает форму создания пустой карты; `hasOpenDraft()` позволяет host предупредить о закрытии незавершённой формы. Readonly скрывает авторские действия. `features.editing=false` выключает формы, а импорт регулируется отдельным `importButton`. Selector терминологии выключен по умолчанию и сохраняет opt-in совместимость.

## 4. Проверка

```powershell
npm run typecheck
npm run build
npm run test:web
```

Наблюдаемый браузерный проход: Chromium + Firefox, 36/36 PASS. Семь новых сценариев в каждом браузере проверяют создание карты, текст, стабильные ссылки, перестановку, C++-ошибки, удаление, оценки/пересечения/codeRefs, readonly, клавиатуру и отмену запоздалой проверки. Одиннадцать прежних сценариев каждого браузера проходят регрессию.

Первый проход выявил необходимость отдельных label/for у select и явного Tab wrap у модального окна; исправления входят в этот дифф. Значение E_INTENT_CYCLE сверено с фактическим движком.
